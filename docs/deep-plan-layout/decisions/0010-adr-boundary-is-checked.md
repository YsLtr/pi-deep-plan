# D10. ADR 与话题决策的边界由检查守住,不只靠约定

- **结论**: `docs/adr/` 放**跨话题**硬决策,`docs/<topic>/decisions/` 放**话题内**决策。
  同一决策同时出现在两处即视为漂移,由 `crossPostedDecisions()`(`src/state.ts`)检出,
  `deep_plan_review` 把它并进 `problems` 退回,并指名是哪个条目文件与 `docs/adr/` 重复。
- **依据**: 本话题的「开放问题」原先把这条留待执行阶段决定(见总纲)。
  实做后发现两处副本会各自演化,而读者翻到哪一份是随机的 —— 这正是 D1 要消灭的
  「同一话题两份真相」。参照条目非空校验(V3)的先例:`deep_plan_review` 已有把
  「文件层面的坏味道」变成可退回问题的机制(`src/index.ts` 的 `problems` 列表),
  这条边界只是往里再加一条。
  比较用正文文本(空白归一后做子串匹配),不依赖文件名或序号 —— 编号会重排,文本不会。
- **置信度**: 中
- **备选**: 「只写进 `plan-format.md` 与 `SKILL.md` 的措辞,不加检查」被否决 —— 那正是本次改动
  之前的状态,已在同一个话题里导致过一次文档违规(总纲把 9 条决策塞在子标题里)。
  「用文件名/编号比对」被否决 —— 两处的编号空间不同(ADR 全局递增、话题内各自递增),
  同一个决策完全可能一边是 0002、一边是 0007。
