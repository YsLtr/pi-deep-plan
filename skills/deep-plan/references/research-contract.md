# 子代理查证契约

P2 的一切**事实**由子代理查，绝不问用户。决策由自己下。

## 派发规则

- **一次性启动全部并行助手**：用一次 `subagent` 调用的 `children` 数组，不得拆分为多次调用。
- **并发 ≤ 3**。单个子代理的启动开销达数千 token；无并行收益时不得增加并发数量。
- **简报自包含**：子代理看不到当前对话。必须写明目标、相关文件路径、约束与期望输出格式。
- **任务不重叠**：每个子代理负责不同的模块或主题，避免重复工作。
- **先验证再采信**：子代理报告返回后，先核对文件是否存在、输出是否非空、结论是否有路径与行号支撑。
- 报告写入 scratch 目录（如 `.pi/tmp/`），不得让子代理向仓库写入正式产物。

## 现有代理

| 代理 | 用途 |
|------|------|
| `researcher` | 联网事实调研，多角度检索与交叉验证，产出带 URL 的中文报告 |
| `scout` | 只读代码库侦察，返回文件路径:行号级别的现状地图 |
| `code-reviewer` | 对已有改动做无预设立场的审查 |

## 查证报告大纲（子代理须按此结构返回）

```
Verified Facts            每条附证据（路径与行号,或 URL）
Open Unknowns             未能查证、需上级判定的事项
Design Question Evidence  因本报告获得答案的自问自答问题
Plan Readiness            ready / ready-with-assumptions / blocked
```

硬性要求：

- **只证明现状，不提供方案。** 方案由执行者负责，不由子代理提供。
- 每条结论必须可追溯。缺少证据的推断须标注 `[推断]`，不得混入 `Verified Facts`。

## 停止查证的判据

须同时满足下列全部条件，方可进入 P3：

1. 设计树上每个 frontier 问题都有答案（经查证获得或由执行者自行判定）。
2. 不存在低置信度答案被当作高置信度使用的情形 —— 低置信度答案均已写入「可变决策表」。
3. 不存在未解决的来源冲突；存在冲突时写入「开放问题」并标注双方来源。
4. 「执行步骤」的每一步都能给出验收方式。

任一条件不满足 → 继续查证或继续自问，**不得**把问题转交用户。
