# 01 写入门禁 / 02 · 只读命令门禁

## 1. 拦截范围

文档阶段**只允许只读命令**。执行阶段完全跳过这条门禁(`src/index.ts:198`)。

```
bash / powershell
      ↓
  分词 (shell-quote)  ← 引号与操作符感知
      ↓
  拆出每个简单命令的 argv
      ↓
  argv 逐个判定:拒绝清单 → 白名单 → 逐命令参数规则
      ↓
  全部通过才放行
```

**【规则】** 判定结果只有两种:全部简单命令都通过 → 放行;任何一个不通过 → 整体拒绝并给出原因(`src/readonly.ts:78-83`)。

**【依据】** 一条命令可能包含多段(`a && rm -rf x`)。仅判定「开头那个命令」会漏掉后半段,故必须拆开逐段判定。

## 2. 分词与正则的实现选择

`src/readonly.ts:1-18` 记录了这条规则的原因。早期实现直接在原始命令字符串上跑正则、并按 `|` / `&&` / `;` 分割,不理会引号,结果是:

| 命令 | 错误的分割结果 |
| --- | --- |
| `grep -rn "a\|b" src/` | 在引号**内部**的分隔符上断开 |
| `wc -l $(find src -type f \| sort)` | 留下悬空的 `sort)` 片段 |
| `cd <dir> && rg x src/` | `cd` 不在白名单里,整条命令被拒 |

**【规则】** 命令必须先经 `shell-quote` 分词(`src/readonly.ts:18`),再在 **argv 层面**判定。不得在原始字符串上做正则匹配来决定放行。

**【依据】** 字符串层面的判定无法区分「引号里的分隔符」与「真实的分隔符」。前者是数据,后者是控制流 —— 混淆两者将同时造成误拒(把 `grep "rm -rf"` 当成含 `rm` 而拒绝)和误放(把引号里的内容当命令)。分词把两者分开是唯一可靠的做法。

## 3. 三类清单

### 3.1 拒绝清单 `DENIED_BINARIES`(`src/readonly.ts:38-48`)

按用途分六组,**命中即拒,不接受任何参数**:

| 组 | 命令 |
| --- | --- |
| 提权与间接执行 | `sudo` `doas` `su` `runas` `eval` `exec` `source` |
| 文件增删改移 | `rm` `rmdir` `mv` `cp` `mkdir` `touch` `install` `patch` `rsync` |
| 权限与节点 | `chmod` `chown` `chgrp` `ln` `mkfifo` `mknod` `truncate` `dd` `shred` `sponge` |
| 输出与批处理 | `tee` `xargs` |
| 进程与服务 | `kill` `pkill` `killall` `reboot` `shutdown` `systemctl` `service` `crontab` `at` |
| 归档与子 shell | `mount` `umount` `tar` `zip` `unzip` `gzip` `gunzip` `bash` `sh` `zsh` `fish` `cmd` `powershell` `pwsh` |

**【规则】** 新增写类命令、或任何能启动任意子进程的命令(解释器、shell),必须加进这张表。

**【依据】** `xargs` / `tee` 本身不是写命令,但这两个命令把「参数里的命令」变成实际执行的命令 —— 仅判定 `xargs` 而不判定 `xargs` 后面的内容等于给出后门。同理 `bash -c "..."` / `sh -c` / `source` 能把任意字符串变成命令,故整个解释器家族直接拒。

### 3.2 白名单 `READ_ONLY_BINARIES`(`src/readonly.ts:50-68`)

**不在白名单的一律拒**(`src/readonly.ts:178`:「不在只读白名单」)。分组:

| 组 | 命令 |
| --- | --- |
| 文件查看 | `cat` `head` `tail` `less` `more` `nl` `tac` `wc` `file` `stat` `du` `df` `tree` `ls` `pwd` `realpath` `readlink` `basename` `dirname` `strings` `xxd` `od` |
| 文本处理 | `sort` `uniq` `cut` `tr` `column` `sed` `awk` `jq` `yq` `comm` `join` `paste` `diff` `expr` `seq` `test` `[` `true` `false` `:` |
| 搜索 | `rg` `grep` `ag` `ack` `fd` `find` `which` `where` `whereis` `type` |
| 环境与系统 | `echo` `printf` `env` `printenv` `uname` `whoami` `id` `hostname` `date` `cal` `uptime` `ps` `top` `htop` `free` `man` `info` `lesspipe` |
| 校验和 | `md5sum` `sha1sum` `sha256sum` `cksum` |
| VCS 与包/运行时元数据 | `git` `npm` `pnpm` `yarn` `bun` `cargo` `go` `node` `python` `python3` `py` |
| 无害 | `cd` |

**【规则】** 白名单里的命令若**带参数即可写**,必须另加逐命令参数规则(见 §5);不得仅依赖「名字在白名单里」。

**【依据】** `sed` / `awk` / `find` 均能写文件或执行命令。名单里有这三个命令是因为文档阶段确实需要这三个命令做只读检索,代价是必须补参数级检查。

### 3.3 特殊处理

| 命令 | 处理 | 行 |
| --- | --- | --- |
| `env` | 跳过 `-u/--unset` 与其他选项;裸 `env` 只打印环境 → 放行;否则把剩余部分当作被包装的命令再判 | `:166-170` |
| `command` | `-v` / `-V` 只查询 → 放行;否则把剩余部分再判 | `:171` |
| `pi` | **只允许** `-h` `--help` `-V` `--version`;其余拒 —— 该命令会启动可写入的 agent | `:172-177` |
| `VAR=val` 前缀 | 直接跳过,不消耗命令名;整条只有赋值时放行(不产生进程) | `:156-159` |

## 4. 操作符

| 类别 | 操作符 | 处理 | 行 |
| --- | --- | --- | --- |
| 写重定向 `WRITE_OPS` | `>` `>>` `>\|` `<>` `>&` `<&` `&>` `&>>` `<` `<<` `<<-` `<<<` `>(` `<(`` | 默认拒;经 `isHarmlessRedirect` 判定无害才放行 | `:27-29`,`:140-143` |
| 分隔 `SEQUENCE_OPS` | `\|` `\|&` `&&` `\|\|` `;` `;;` `;&` `;;&` | 拆开,各自独立判定 | `:35`,`:144` |
| 子 shell | `(` `)` | 直接拒:「子 shell 括号无法判定只读性」 | `:138` |
| 后台 | `&` | 直接拒:「后台执行(&)不允许」 | `:139` |
| 其他 | 任何未列出的操作符 | 拒:「未知操作符」 | `:144` |
| 注释 | `#` 起 | 截断,其后不再判定 | `:132` |

无害重定向的判定(`src/readonly.ts:364-370`):

| 操作符 | 放行条件 |
| --- | --- |
| `>&` / `<&` | 目标为**纯数字**(复制描述符,如 `2>&1`)或 `-`(关闭) |
| `>` / `>>` | 目标属于 `NULL_DEVICE`,即 `/dev/null` 或 `nul`(大小写不敏感) |
| 其余 | 一律不放行 |

`NULL_DEVICE` = `{"/dev/null", "nul"}`(`src/readonly.ts:32`)。

**【规则】** 只有「复制描述符」与「写入空设备」两种重定向算无害。`>& file` 这种**省略 fd 号**的写法仍是写文件,必须拒。

**【依据】** `2>&1` 与 `>&2` 只动已打开的描述符,`> /dev/null` 丢弃字节,两类重定向均不触碰真实文件 —— 若不豁免,`cmd 2>/dev/null` 这种最常见的检索形式会被误拒。而 `>& file` 在 shell 里等价于「把 stdout 和 stderr 都写进 file」,是真实的写操作,故按目标是否为纯数字区分。

## 5. 逐命令参数规则

| 命令 | 危险参数 | 规则 | 行 |
| --- | --- | --- | --- |
| `find` | `-exec` `-execdir` `-ok` `-okdir` `-delete` `-fprint*` `-fls` | 命中即拒 | `:220` |
| `fd` | `-x` `-X` `--exec` `--exec-batch` | 命中即拒 | `:221` |
| `sed` / 通用 | `--in-place` `--inplace` `-i` | 命中即拒 | `:222` |
| `git` | 全局 `-C` `--git-dir` `--work-tree` `--exec-path` `--namespace` `--super-prefix` `--config-env` | 命中即拒(能改判定基准) | `:223` |
| `git` | 子命令须在只读子命令集合内(`status` `diff` `log` `show` `blame` `ls-files` 等) | 不在即拒 | `:225-233` |
| `git branch` | 只读旗标(`-l` `--list` `-a` `--all` `-r` `-v` …) | 只有这些形态放行 | `:235-236` |
| `npm` / `pnpm` / `yarn` / `bun` | 子命令须在 `ls` `list` `view` `info` `outdated` `doctor` 等只读集合内 | 不在即拒 | `:238-241` |
| `cargo` | 同上,只读子命令集合 | 同上 | `:243-` |

**【规则】** 白名单命令的**子命令**必须各自有一份只读集合;不得因父命令在白名单里而放行该父命令的全部子命令。

**【依据】** `git` 既是只读工具又是最常用的写工具(`git commit` / `git add`)。整体放行等于文档阶段可以提交 —— 而「文档阶段不做任何改动」正是这一阶段的目的。同理 `npm install`、`cargo build` 均会产生文件。

**【不采纳】** 不做「`git` 全放行,由提交归属约定约束」。约定不是强制,门禁的存在意义就是不依赖约定。

## 6. 嵌套与替换

| 机制 | 常量 | 规则 |
| --- | --- | --- |
| 命令替换 | `SUBST_PLACEHOLDER = "__dp_subst__"`(`:24`) | 先把 `$(...)` / 反引号内容抽出并占位,再把**占位符指向的原命令**递归判定 |
| 递归深度 | `MAX_DEPTH = 5`(`:21`) | 超过即拒:「嵌套过深,拒绝判定」(`:92`) |
| 引号不闭合 | — | 拒:「无法解析命令(引号不闭合或括号不配对)」(`:93`) |

**【依据】** `$(rm -rf x)` 是一条能删文件的命令,但该命令出现在**参数位置**。若仅判定外层命令名(`echo`),就会漏判。先抽替换体、再递归判定内层,才能覆盖到。深度上限防止 `$(a $(b $(c ...)))` 构造出判定成本爆炸的输入。

## 7. 已知限制

| # | 限制 | 说明 |
| --- | --- | --- |
| L1 | **只覆盖 `bash` / `powershell` 两个工具名** | 其他能执行命令的工具(`src/index.ts:200`)不在判定范围 |
| L2 | **不判断目标路径** | 门禁只判定「命令是否只读」,不看命令读哪个文件。`cat /etc/passwd` 在白名单内且被放行 —— 文档阶段本就需要读遍仓库与系统信息 |
| L3 | **白名单是人工维护的** | 常见但未列入的命令(如 `bat`、`delta`)会被拒。补救是把命令名加进白名单,不是放宽判定 |
| L4 | **`node` / `python` 在白名单里** | 这两个命令能写文件。判定只到命令名与部分参数,`node -e "..."` 不在拒绝范围内 —— 这是已知的绕过路径,属「尽力而为」的边界 |
| L5 | **执行阶段完全跳过** | `src/index.ts:198` 直接 return。执行阶段没有命令限制,这是刻意的(见 `../00-总览/01` 的 N3) |
| L6 | **依赖 `shell-quote` 的解析结果** | 该库无法解析的语法会被判为「无法解析」而被拒(fail closed),但解析结果本身的正确性不由本项目保证 |
