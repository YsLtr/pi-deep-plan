# 03 规划流程

## 本部分讲什么

本部分规定 **agent 在文档阶段被要求做什么**。这一层全部是**纪律**(写进系统提示的文案),不是门禁:门禁只管「能不能写」(`../01-写入门禁/`),这里是「该怎么做」。

```
        /deep-plan <目标>
               ↓
   ┌───────────────────────┐
   │ 01 提问式规划          │  设计树 + frontier,自问自答
   └───────────┬───────────┘
               ↓ 需要事实
   ┌───────────────────────┐
   │ 02 子代理查证          │  大范围检索外包,报告落 scratch
   └───────────┬───────────┘
               ↓
   ┌───────────────────────┐
   │ 03 成文与收尾          │  写成文档 → deep_plan_review → 用户批准
   └───────────┬───────────┘
               ↓ 执行中发现矛盾
   ┌───────────────────────┐
   │ 04 冲突回退            │  deep_plan_revise,回到文档阶段
   └───────────────────────┘
```

## 关联

- **同步要求**:本部分与 `../skills/deep-plan/SKILL.md` 是同一套纪律的两份表达(前者给维护者,后者给模型)。改一处必须改另一处。
- **上游**:纪律通过 `before_agent_start` 注入(`../04-扩展接口/02`)。
- **下游**:产物形状由 `../02-文档规范/` 规定;门禁保证纪律不被绕过。
