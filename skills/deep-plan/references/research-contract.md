# 子代理查证契约

P2 的一切**事实**由子代理查，绝不问用户。决策由自己下。

## 派发规则

- **一次启动全部并行助手**：用一次 `subagent` 调用的 `children` 数组，不要拆成多次调用。
- **并发 ≤ 3**。启动开销数千 token，无并行收益就不堆数量。
- **简报自包含**：子代理看不到当前对话。必须写清目标、相关文件路径、约束、期望输出格式。
- **任务不重叠**：每个子代理负责不同模块/主题，避免重复劳动。
- **先验证再采信**：子代理报告回来先核对文件是否存在、输出是否非空、结论是否有路径行号支撑。
- 报告落到 scratch 目录（如 `.pi/tmp/`），不要让子代理往仓库里写正式产物。

## 现有代理

| 代理 | 用途 |
|------|------|
| `researcher` | 联网事实调研，多角度检索 + 交叉验证，产出带 URL 的中文报告 |
| `scout` | 只读代码库侦察，返回文件路径:行号级别的现状地图 |
| `code-reviewer` | 对已有改动做无偏见审查 |

## 查证报告大纲（要求子代理按此结构返回）

```
Verified Facts       每条附证据（路径:行号 或 URL）
Open Unknowns        查不到的、需上级决策的
Design Question Evidence  哪些自问自答的问题因此有了答案
Plan Readiness       ready / ready-with-assumptions / blocked
```

硬规则：

- **只证明现状，不给方案。** 方案是你的活，不是子代理的活。
- 每个结论必须可追溯。没有证据的推断标 `[推断]`，不得混入 `Verified Facts`。

## 停止查证的判据

满足全部条件才进入 P3：

1. 设计树上每个 frontier 问题都有答案（查证得来或自己下的决策）。
2. 没有低置信度的答案被当成高置信度用——低置信度的都进了「可变决策表」。
3. 没有未解决的来源冲突；有冲突的写进「开放问题」并标注双方来源。
4. 「执行步骤」的每一步都能说出验收方式。

任一不满足 → 继续查证或继续自问，**不要**把问题抛给用户。
